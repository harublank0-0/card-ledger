# card-ledger

Open-source (AGPLv3), self-hostable personal finance and subscription tracker. Working MVP: sign-in, cards (last4 only), subscriptions, email reminders, transactions with refunds, card statements and payments, and a dashboard home page. Data export, account deletion, demo data, the Docker/compose stack, the self-hosting guide (`docs/self-hosting.md`) and backup/restore (`docs/backup-restore.md`) are built, as are the real `README.md` (screenshots of the demo data in `docs/screenshots/`), `CONTRIBUTING.md`, `SECURITY.md` and `CODE_OF_CONDUCT.md`, and GitHub Actions CI (`.github/workflows/`, [ADR 0009](docs/decisions/0009-ci-minimal-pinned-secret-free.md): SHA-pinned first-party actions only, no secrets; `sh scripts/check-dco.sh origin/main..HEAD` runs the DCO check locally) and the issue/PR templates (`.github/ISSUE_TEMPLATE/`, `pull_request_template.md`), plus the pre-publication audit (`docs/pre-publication-audit.md`; `pnpm run licenses:check` enforces an AGPL-3.0-only dependency-licence allowlist and runs inside `pnpm test`). Every roadmap ticket through Phase 3 is done; what remains is the manual GitHub setup listed in the audit document and the open items of the model-assisted code and security review (`docs/pre-publication-audit.md` section 8; it is not an independent human audit). The repository is public at `github.com/haruBlank0-0/card-ledger`; CI is green there (`verify`, `docker` and `audit` on push, `dco` on a test pull request, runner pinned to `ubuntu-24.04`), the backup drill passed there when started on demand, and private vulnerability reporting is on (all checked 2026-10-11), and `main` is protected by the ruleset `protect-main` (a pull request and the three CI checks are required; read back through the API on 2026-10-11), while the repository description and topics are still to be set.

Planning docs (proposed, not yet implemented): `docs/architecture.md`, `docs/database.md`, `docs/roadmap.md`, `docs/decisions/`. Work one roadmap ticket at a time; read the relevant doc sections first and update docs when a decision changes.

## Product principles
- One codebase for self-hosted and any future cloud; no feature locks, license checks, or edition flags.
- No telemetry and no required calls to external services; email (SMTP) is optional and operator-configured.
- Never store full card numbers, CVV, PIN, or banking credentials (`last4` only). Never commit secrets or real financial data; demo data is synthetic.
- Every domain row has `userId`; every query is user-scoped; enforce auth in server functions/middleware, not only route guards; each feature needs cross-user and unauthenticated tests.
- Money = integer minor units + ISO 4217 currency, never floats, never summed across currencies. Date-only deadlines are calendar dates (`@db.Date`); timestamps are UTC.
- Validate input on the server with `.validator()` + Zod. Keep financial logic in pure modules (no React/Prisma).

## Stack
- TanStack Start + Router (file-based routes in `src/routes`, generated `src/routeTree.gen.ts` — never edit by hand), React 19 with React Compiler, Vite 8, Nitro server (`pnpm run build` → `node .output/server/index.mjs`).
- TanStack Query (SSR-integrated in `src/router.tsx`), TanStack Form.
- Prisma 7 + Postgres via `@prisma/adapter-pg`; client generated to `src/generated/prisma` (gitignored; run `pnpm run db:generate`). Schema: `prisma/schema.prisma`.
- Better Auth (email/password, persisted via the Prisma adapter, `SIGNUP_MODE` policy): `src/lib/auth.ts`, `src/lib/auth-client.ts`, route `src/routes/api/auth/$.ts`.
- MCP endpoint `/mcp` is disabled (404) unless `MCP_ENABLED=true` and then requires a session; no tools registered yet.
- `src/start.ts` holds the global server-function middleware. Having a start instance **replaces** TanStack Start's default request middleware, so CSRF protection is re-added there explicitly; do not remove it. Every server function's errors pass through `toClientError` (`src/lib/client-errors.ts`): throw a plain `Error` with a message written for people for expected failures, and anything else (Prisma, pg, TypeError, ...) reaches the browser only as a generic message while the server logs its class.
- Request bodies over 1 MiB are refused with 413 by a Nitro middleware (`src/server/body-limit.ts`, registered in `vite.config.ts` for `/**`; it must be middleware, because an error thrown from a Nitro `request` hook is only logged). In `SIGNUP_MODE=first-user`, sign-up requests run under a Postgres advisory lock (`src/lib/signup-lock.server.ts`, applied in `src/routes/api/auth/$.ts` through `handleAuthPost`) so two simultaneous first sign-ups cannot both create an owner. Waiters queue in the process before taking the lock, so a burst cannot use up the connection pool and starve the request that owns it.
- `/api/health` is deliberately unauthenticated (200, or 503 with pass/fail per check only) for Docker and proxies; it touches no domain table. A Nitro plugin (`src/server/startup.ts`) validates the environment at boot and logs variable names only; it also warns (and still starts) when `SIGNUP_MODE=open` is combined with SMTP, because email addresses are not verified. Server logs are JSON lines from `src/lib/logger.server.ts`: primitives only, never amounts, notes or error messages (use `errorClass`).
- Features live in `src/features/<name>/` (`*.schemas.ts` Zod, `*.service.server.ts` user-scoped Prisma, `*.functions.ts` `createServerFn` + `authMiddleware`, `*.logic.ts` pure). Routes in `src/routes/_authed/` are guarded for UX only; `/` is the dashboard. Component render tests use `src/test/render.tsx` (in-memory router, static HTML, no DOM library).
- Tailwind CSS 4, shadcn/ui (new-york, zinc, lucide) in `src/components/ui`, Biome for lint/format (tabs, double quotes).
- Typed env via `@t3-oss/env-core` in `src/env.ts` (client vars need `VITE_` prefix).

## Conventions
- Package manager is **pnpm**, pinned in `package.json` (`packageManager`, provided by Corepack: `corepack enable`); Node.js is pinned by `.nvmrc` (`nvm use`) and `engines`, and `.npmrc` makes installs refuse anything else. pnpm 12 reads its settings (security `overrides`, allowed dependency build scripts) from `pnpm-workspace.yaml`, not from `package.json`. `pnpm-lock.yaml` is the only lockfile (`src/toolchain.test.ts`); never run `npm install`, which ignores those settings. Add components with `pnpm dlx shadcn@latest add <component>`.
- Import alias `#/*` → `src/*` (also `@/*` in tsconfig). TypeScript is strict with no unused locals/params.
- DB scripts load `.env.local` (`DATABASE_URL` required; Better Auth needs `BETTER_AUTH_SECRET`).
- Local services: `docker compose -f compose.dev.yaml up -d` (Postgres on 127.0.0.1:5434; Mailpit SMTP 127.0.0.1:1025, inbox http://localhost:8025). Reminders: `pnpm run reminders:send`. After changing `prisma/schema.prisma`, run `pnpm run db:migrate` and **restart `pnpm run dev`** (it caches the old Prisma client). `.env.local` needs `DATABASE_URL`, `BETTER_AUTH_URL=http://localhost:3100`, `BETTER_AUTH_SECRET` (32+ chars).
- Self-hosting: `compose.yaml` runs `db`, a one-shot `migrate`, `app` and `reminders` from one `Dockerfile` image ([ADR 0008](docs/decisions/0008-container-image-and-compose-topology.md)); it needs `POSTGRES_PASSWORD` and `BETTER_AUTH_SECRET` in `.env` (template: `.env.example`, kept in sync with `src/env.schema.ts` and `compose.yaml` by a test; its project name is `card-ledger-selfhost` so it never touches the dev stack), publishes the app on 127.0.0.1 only and never publishes the database. `pnpm run docker:smoke` builds it in a throwaway project and checks health, no DB port, loopback-only, non-root and restart persistence (needs Docker). `BETTER_AUTH_URL` must equal the public URL exactly; cookies are `Secure` only when it is `https://`.
- Backups: `pnpm run backup` (`scripts/backup.sh`, `pg_dump` via the `db` container into git-ignored `backups/`, `BACKUP_KEEP`), `scripts/restore.sh <file> [--force]`, `scripts/restore-test.sh <file> [--keep]` (restore a real backup into a separate throwaway project with reminders off; never hand-roll this with `COMPOSE_PROJECT_NAME`), and `pnpm run backup:drill` (throwaway project; run it after touching `scripts/`). Backups hold all users' financial data: never commit or log them.
- Commands: `pnpm run dev` (port 3100, strict), `pnpm run check` (Biome), `pnpm run typecheck`, `pnpm test` (Vitest; integration tests auto-create `<db>_test`), `pnpm run build`, `pnpm run db:migrate|studio|seed`. `pnpm run db:seed` creates the synthetic demo account (prints a one-time password; refuses `NODE_ENV=production`). Exports are at `/api/export/json` and `/api/export/csv/<entity>` (format: `docs/data-format.md`).
- Biome ignores `src/routeTree.gen.ts` and `src/styles.css`.
- UI rules, each pinned by a test: screens run mutations through `useAction` (`src/lib/use-action.ts`: one call at a time, failures shown via the `toClientError` allowlist, route data reloaded; no hand-rolled `catch (e) { setError(e.message) }`); `FormField` wires `aria-invalid`/`aria-describedby`; every page sets `head: pageTitle("...")`; detail loaders check `isUuid` and only a `null` from the server becomes `notFound()` (never `catch { throw notFound() }`); "today" and date defaults come from the user's time zone via a server function, never `Intl.DateTimeFormat().resolvedOptions().timeZone` in UI code; search params fall back with `.catch(undefined)`. Server side: anything that depends on a card's current state while writing statements or changing its currency takes `lockCard` (`src/lib/card-lock.server.ts`) and reads from the returned row.
