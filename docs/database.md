# Card Ledger — Database Design

Status: partially implemented. `prisma/schema.prisma` currently contains the Better Auth models, `PaymentMethod` and `Subscription` (with CHECK constraints added by migration `domain_checks`). The remaining models below are proposed. Prisma 7.10, `prisma-client` generator (output `src/generated/prisma`), PostgreSQL via `@prisma/adapter-pg`. Schema changes go through `prisma migrate` migrations committed to the repo.

## 1. Conventions

- **Ownership**: every domain table has `userId` referencing Better Auth's `User`, indexed, and included in per-user unique constraints.
- **IDs**: new domain entities use UUID primary keys (`String @id @default(uuid(7)) @db.Uuid` — confirm `uuid(7)` support in the installed Prisma during M-01, fall back to `uuid()`). Better Auth models are generated by its CLI/Prisma adapter and keep its default string ids; `userId` columns therefore are `String` (matching `User.id`), not `@db.Uuid`. During F-03, check whether Better Auth can generate UUID ids and switch only if it needs no custom hacks.
- **Money**: `Int` minor units (`amountMinor`) + `currency Char(3)` (ISO 4217). Never `Float`. Amounts stored positive; direction is encoded by `type` (expense/refund), not sign. Rationale: [ADR 0004](./decisions/0004-money-integer-minor-units.md). A single value caps at ~21.4M major units, enough for personal finance; widening to `BigInt` later is a mechanical migration.
- **Dates**: date-only business values use `@db.Date`; real moments use `DateTime` (UTC). Rationale: [ADR 0005](./decisions/0005-calendar-dates-and-timezones.md).
- **Timestamps**: `createdAt @default(now())`, `updatedAt @updatedAt` on every domain table.
- **Deletion**: no hard deletes of financial history. Payment methods, categories, and subscriptions are **archived** (`archivedAt`). Foreign keys between domain entities use `onDelete: NoAction` (Prisma's name for `ON DELETE NO ACTION`): deleting a referenced row on its own is blocked like `Restrict`, but the check runs at statement end, so deleting a `User` can cascade through both tables. A true `RESTRICT` is checked immediately and would make account deletion fail depending on cascade order. Only the `User` relation uses `onDelete: Cascade` (account deletion removes everything the user owns).
- **Naming**: Prisma models PascalCase, table/column mapping via `@@map`/`@map` to `snake_case`; enums for closed sets.
- **Sensitive data**: no PAN, CVV, PIN, or credentials anywhere. `PaymentMethod.last4` only.

## 2. Better Auth models

Generated from the Better Auth Prisma adapter (`User`, `Session`, `Account`, `Verification`) in F-03. We preserve them as generated and add one relation field per domain model on `User`. Do not hand-modify their columns; regenerate when Better Auth is upgraded.

## 3. Domain models (proposed)

Illustrative Prisma; final field details are settled in each feature ticket.

```prisma
enum BillingUnit { WEEK MONTH YEAR }          // quarterly = 3 MONTH; custom = N of any unit
enum SubscriptionStatus { ACTIVE CANCELLED EXPIRED }
enum TransactionType { EXPENSE REFUND }
enum NotificationKind { SUBSCRIPTION_RENEWAL SUBSCRIPTION_EXPIRY CANCELLATION_DEADLINE CARD_PAYMENT_DUE }
enum NotificationStatus { PENDING SENT FAILED }

model Category {
  id         String    @id @default(uuid()) @db.Uuid
  userId     String
  name       String
  archivedAt DateTime?
  createdAt  DateTime  @default(now())
  updatedAt  DateTime  @updatedAt
  user         User          @relation(fields: [userId], references: [id], onDelete: Cascade)
  transactions Transaction[]
  @@unique([userId, name])
}

model PaymentMethod {
  id               String    @id @default(uuid()) @db.Uuid
  userId           String
  name             String                  // "Daily card"
  issuer           String?
  last4            String    @db.Char(4)   // digits only, validated
  currency         String    @db.Char(3)
  creditLimitMinor Int?
  statementDay     Int?                    // 1-31, clamped to month length
  paymentDueDay    Int?                    // 1-31, clamped to month length
  archivedAt       DateTime?
  createdAt        DateTime  @default(now())
  updatedAt        DateTime  @updatedAt
  user          User            @relation(fields: [userId], references: [id], onDelete: Cascade)
  subscriptions Subscription[]
  transactions  Transaction[]
  statements    CardStatement[]
  @@index([userId, archivedAt])
}

model Subscription {
  id                   String             @id @default(uuid()) @db.Uuid
  userId               String
  paymentMethodId      String?            @db.Uuid
  name                 String
  amountMinor          Int
  currency             String             @db.Char(3)
  intervalCount        Int                @default(1)
  intervalUnit         BillingUnit
  anchorDate           DateTime           @db.Date   // first/known billing date; renewals derive from this
  status               SubscriptionStatus @default(ACTIVE)
  autoRenew            Boolean            @default(true)
  expiresOn            DateTime?          @db.Date
  cancellationDeadline DateTime?          @db.Date
  cancelledOn          DateTime?          @db.Date
  notes                String?
  archivedAt           DateTime?
  createdAt            DateTime           @default(now())
  updatedAt            DateTime           @updatedAt
  user          User           @relation(fields: [userId], references: [id], onDelete: Cascade)
  paymentMethod PaymentMethod? @relation(fields: [paymentMethodId], references: [id], onDelete: Restrict)
  transactions  Transaction[]
  @@index([userId, status])
  @@index([userId, expiresOn])
}

model Transaction {
  id              String          @id @default(uuid()) @db.Uuid
  userId          String
  type            TransactionType
  amountMinor     Int                          // > 0
  currency        String          @db.Char(3)
  occurredOn      DateTime        @db.Date     // user-facing transaction date
  description     String
  notes           String?
  categoryId      String?         @db.Uuid
  paymentMethodId String?         @db.Uuid
  subscriptionId  String?         @db.Uuid     // set when the user records an actual charge
  refundOfId      String?         @db.Uuid     // REFUND -> original EXPENSE
  createdAt       DateTime        @default(now())
  updatedAt       DateTime        @updatedAt
  user          User            @relation(fields: [userId], references: [id], onDelete: Cascade)
  category      Category?       @relation(fields: [categoryId], references: [id], onDelete: Restrict)
  paymentMethod PaymentMethod?  @relation(fields: [paymentMethodId], references: [id], onDelete: Restrict)
  subscription  Subscription?   @relation(fields: [subscriptionId], references: [id], onDelete: Restrict)
  refundOf      Transaction?    @relation("Refunds", fields: [refundOfId], references: [id], onDelete: Restrict)
  refunds       Transaction[]   @relation("Refunds")
  @@index([userId, occurredOn])
  @@index([userId, paymentMethodId, occurredOn])
  @@index([userId, categoryId, occurredOn])
}

model CardStatement {
  id                  String   @id @default(uuid()) @db.Uuid
  userId              String
  paymentMethodId     String   @db.Uuid
  periodStart         DateTime @db.Date
  periodEnd           DateTime @db.Date
  dueDate             DateTime @db.Date
  statementBalanceMinor Int                       // entered from the bank statement
  minimumDueMinor     Int?
  currency            String   @db.Char(3)        // must equal the card's currency
  createdAt           DateTime @default(now())
  updatedAt           DateTime @updatedAt
  user          User              @relation(fields: [userId], references: [id], onDelete: Cascade)
  paymentMethod PaymentMethod     @relation(fields: [paymentMethodId], references: [id], onDelete: Restrict)
  payments      StatementPayment[]
  @@unique([paymentMethodId, periodStart, periodEnd])
  @@index([userId, dueDate])
}

model StatementPayment {
  id          String   @id @default(uuid()) @db.Uuid
  userId      String
  statementId String   @db.Uuid
  amountMinor Int                                  // > 0, same currency as statement
  paidOn      DateTime @db.Date
  notes       String?
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
  user      User          @relation(fields: [userId], references: [id], onDelete: Cascade)
  statement CardStatement @relation(fields: [statementId], references: [id], onDelete: Restrict)
  @@index([userId, paidOn])
}

model NotificationPreference {
  id                 String   @id @default(uuid()) @db.Uuid
  userId             String   @unique
  timezone           String   @default("Asia/Kathmandu")   // IANA name, validated
  emailEnabled       Boolean  @default(true)
  offsetsDays        Int[]    @default([7, 3, 1])
  renewalEnabled     Boolean  @default(true)
  expiryEnabled      Boolean  @default(true)
  cancellationEnabled Boolean @default(true)
  paymentDueEnabled  Boolean  @default(true)
  createdAt          DateTime @default(now())
  updatedAt          DateTime @updatedAt
  user User @relation(fields: [userId], references: [id], onDelete: Cascade)
}

model NotificationLog {
  id          String             @id @default(uuid()) @db.Uuid
  userId      String
  kind        NotificationKind
  entityId    String             @db.Uuid     // subscription or statement/payment method id
  eventDate   DateTime           @db.Date     // the date being reminded about
  offsetDays  Int
  channel     String             @default("email")
  status      NotificationStatus @default(PENDING)
  attempts    Int                @default(0)
  lastError   String?                         // short, no sensitive content
  nextAttemptAt DateTime?
  sentAt      DateTime?
  createdAt   DateTime           @default(now())
  updatedAt   DateTime           @updatedAt
  user User @relation(fields: [userId], references: [id], onDelete: Cascade)
  @@unique([userId, kind, entityId, eventDate, offsetDays, channel])   // idempotency / dedupe
  @@index([status, nextAttemptAt])
}
```

`entityId` in `NotificationLog` is intentionally not a foreign key (it points to different tables by `kind`); the log is an audit record and must survive archival. It is deleted with the user.

## 4. Key relationships and constraints

- `User 1—* ` every domain table (cascade from user only).
- `PaymentMethod 1—* Subscription | Transaction | CardStatement` (no action; archive instead of delete).
- `Category 1—* Transaction` (no action; archive instead of delete).
- `Subscription 1—* Transaction` (optional; a transaction links to a subscription only when the user records an actual charge).
- `Transaction 1—* Transaction` (refund → original expense).
- `CardStatement 1—* StatementPayment`.

Additional rules enforced in the service layer (cannot all be expressed in Prisma), with DB `CHECK` constraints added through migration SQL where cheap:

- Foreign IDs referenced in a write must belong to the same `userId` (Prisma FKs do not check ownership).
- `amountMinor > 0`, `last4 ~ '^[0-9]{4}$'`, `statementDay/paymentDueDay BETWEEN 1 AND 31`, `currency ~ '^[A-Z]{3}$'`.
- A refund's `refundOfId` points to an `EXPENSE` of the same user; refunded total cannot exceed the original amount; currency must match.
- A statement payment's currency is the statement's currency (no `currency` column on payments).
- Statement `currency` equals its payment method's `currency`.
- `Subscription.expiresOn`, if set, is not before `anchorDate`.

## 5. Derived values (not stored)

- **Next renewal(s)** of a subscription: computed from `anchorDate` + (`intervalCount`, `intervalUnit`), clamping to month end (anchor Jan 31 + 1 month → Feb 28/29 → Mar 31, always derived from the anchor, never by chaining from the previous clamped date). Respects `status`, `autoRenew`, and `expiresOn`.
- **Statement outstanding**: `statementBalanceMinor − Σ payments`, floored for display at 0 with overpayment shown separately.
- **Dashboard totals**: grouped by currency; refunds subtract from expense totals in the same currency; **statement payments never count as spending**.
- **Utilization**: only meaningful against statement data; the app does not claim to know a card's true balance from manual expenses alone.

## 6. Indexing

Per-user composite indexes listed above cover: transaction list/filter by date, card, category; upcoming subscription queries; statement due-date queries; reminder processing (`status`, `nextAttemptAt`). Add further indexes only when a measured query needs them.

## 7. Migrations and data lifecycle

- Migrations are generated with `npm run db:migrate` (dev) and applied with `prisma migrate deploy` in production (container start).
- Never edit an applied migration. Destructive changes need a documented upgrade note in release notes.
- Backups: `pg_dump` runbook in Phase 2; restore drill documented and tested.
- Account deletion cascades through `User`; export is available before deletion.
- Demo data (ticket M-16) is synthetic, inserted for a clearly named demo user, and refuses to run in production unless forced.
